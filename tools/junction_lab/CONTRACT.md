# Junction Lab implementation contract

This is an offline research harness for three matched policies: `no_advice`, `local_only`, `mesh_informed`. SUMO moves vehicles; the Android-free Kotlin policy decides whether a received observation warrants a queue caution. Simulated human response is a separately labeled adapter. No Android UI, BLE wire protocol, original car assets or production road mode changes in this slice.

## Ownership

- Codex worker: `core/src/main/kotlin/com/jsons/roadmesh/core/junction/`, matching core unit tests, and a `junctionPolicyJar` task in `core/build.gradle.kts` only.
- Antigravity worker: `tools/junction_lab/viewer.html` only; an offline, dependency-free full HTML results viewer.
- Claude worker: independent model review and `tools/junction_lab/REVIEW.md` only. Coordinator implements fixes or assigns follow-up work.
- Coordinator: Python SUMO runner, transport/response adapters, requirements, scenario generation, integration tests, documentation, generated samples and final verification.

## Policy CLI version 1

UTF-8 tab-separated stdin/stdout; diagnostics only stderr. `RESET` clears the bounded local state and responds `OK`. `QUIT` responds `OK` then exits. One response for every input line; malformed commands respond `ERROR\tinvalid_input` without killing the process. Input fields cannot contain tabs/newlines.

`EVAL` fields, in exact order:

1. `EVAL`
2. mode (`no_advice`, `local_only`, `mesh_informed`)
3. recipientId
4. nowMs (nonnegative Long)
5. equipped (`true`/`false`)
6. recipientScope (directed corridor ID)
7. aheadDistanceM (finite Double; observation position minus recipient position)
8. speedMps (finite nonnegative Double)
9. eventId
10. capturedMs (nonnegative Long)
11. expiresMs (exclusive expiry; greater than capture)
12. eventScope
13. sourceId
14. channel (`local`/`mesh`)

An immutable queue observation contains event/source/scope/capture/expiry. Locally simulated forward sensing is labeled hypothetical; mesh events are only generated by equipped observers. No ground-truth queue count or signal state enters policy input.

Output `WARN\tqueue_ahead\t<ageMs>` or `IGNORE\t<reason>`. Reasons must be stable strings. Validate mode/channel/numeric fields, equipped recipient, mode eligibility, same scope, positive ahead distance <= 400 m, future timestamps (strictly reject for this shared simulation clock), age <= 10000 ms, now < expires, and speed > 0.5 m/s. `local_only` rejects mesh input. `mesh_informed` accepts local and mesh. `no_advice` never warns. No speed instruction or priority grant.

For each recipient, at most one warning per 12000 ms across events; repeating an accepted event never warns again within its validity. State must be bounded (default max 512 recipients and max 512 accepted event keys total); expire event keys at expiresMs and idle recipient entries after cooldown. Under pressure reject new work rather than evict live keys. Backward time must be rejected unless RESET. Expiry and duplicate checks happen before output. A single CLI instance is driven serially. `RESET` explicitly begins a new experiment, not a production replay guarantee.

Jar output: `core/build/libs/core-junction-policy.jar`, with Kotlin runtime and a Main-Class. Python uses a persistent `java -jar` subprocess per run. Build command `gradlew :core:test :core:junctionPolicyJar`; use JDK 17 or later that supports the project toolchain. Do not run shared Gradle concurrently with other workers; coordinator will run final Gradle checks.

## Result JSON version 1

Root: `{schemaVersion:1, title:string, assumptions:string[], config:object, seeds:number[], runs:Run[], summary:object}`. All time values in seconds unless field says Ms. Values are measured from synthetic runs; not hardware or real-world improvement claims.

Each Run: `{mode, seed, metrics, frames, warnings, fingerprint}`.

Metrics numeric keys: `scheduledVehicles`, `arrivedVehicles`, `activeVehicles`, `pendingVehicles`, `totalDelayS`, `spillbackDurationS`, `maxQueueExtentM`, `advisoryCount`, `deliveredMessages`, `expiredMessages`, `droppedMessages`, `usefulWarnings`, `meanWarningLeadS`, `conservationErrors`, `teleports`, `collisions`. `meanWarningLeadS` may be null when unobserved. Lead time refers to modeled observation location, not a guaranteed collision-response margin. Include units/definitions in documentation. Avoid presenting collision counts as a safety certification.

Frames at 0.5 s and then each integer second: `{time, queueExtentM, pending, arrived, vehicles:[{id,x,y,speed,equipped}], knowledge:[{recipientId, capturedAt, expiresAt, sourceId, channel}], warnings:[recipientId]}`. Frame warnings include every recipient cautioned since the preceding frame, including intervening half-second steps. SUMO coordinates use x east / y north. The main road runs west to east through junctions around x=200 and x=320; incoming source around x=0, destination around x=540; side arms y=-80..80. Viewer derives bounds from actual frames and uses these junction hints for schematic roads. Knowledge records retain one nearest eligible observation selected per recipient until expiry, not the whole cache or global truth. They may remain visible after the actor leaves policy scope; they do not imply continuing advisory eligibility.

Warnings: `{time, recipientId, sourceId, eventId, capturedAt, expiresAt, channel, x, y, aheadDistanceM, responded:boolean, responseAccepted:boolean, responseAppliedAt:number|null, leadS:number|null}`. `responded` describes the eventual outcome; `responseAppliedAt` identifies when it began. Response acceptance is sampled deterministically per recipient independently of policy-specific RNG call order. It is a simulation assumption, not measured compliance.

`summary` groups metrics by mode (mean/min/max); do not assume benefit. Viewer may calculate from runs if absent. Replay must use exported frames, never generate improved trajectories. Include file input (works over file://), optional fetch of `sample-results.json` beside viewer with a visible failure/upload fallback, seed selection, aligned timeline across the three modes, play/pause, reduced-motion support, compact per-mode metrics, explicit synthetic/unvalidated labels. No network/CDN dependencies and no fabricated demo dataset. No HTML interpolation of arbitrary JSON strings; render untrusted file content with textContent and validate schema/finite numbers.

## Mandatory evidence

Compare identical demand, geometry, seed and exogenous event schedule. Keep RNG for equipment, link loss and driver response independent and stable by actor/message identity. Record complete assumptions and pinned SUMO version. With compliance=0, all three modes must have identical traffic fingerprints. With penetration=0, all three must likewise coincide and issue no warnings. Conservation includes scheduled-but-not-inserted vehicles; SUMO teleports must not hide congestion. A partition/no-delivery run must degrade honestly. These are proposed model tests, not RF, human or road-safety validation.
